# `@cldmv/wisp` v2.0.0 Changelog

**Release Date**: November 2026
**Release Type**: Major
**Branch**: `release/2.0.0`

---

## Overview

`require("@cldmv/wisp")` now returns the module object `{ default, wisp, wispSync }`, the same exports `import` gives you, instead of the `wisp` function. That is the only change to the public surface, and it only affects CommonJS callers that called the result of `require()` directly. ESM `import` is unchanged, and so are the options, the JSON loading behaviour and the supported Node.js range.

The rest of the release is test and CI housekeeping and development-dependency bumps. The package still has no runtime dependencies.

---

## 💥 Breaking Changes

### The CommonJS entry returns the module object ([#86](https://github.com/CLDMV/wisp/pull/86), fixes [#85](https://github.com/CLDMV/wisp/issues/85))

`src/index.cjs`, published as `dist/index.cjs`, is now the generic CLDMV shim. It loads `index.mjs` through synchronous `require(esm)` and hands back what `import` sees. The ESM entry exports two distinct values, `wisp` and `wispSync` (`default` is `wisp`), so `require("@cldmv/wisp")` returns the module object `{ default, wisp, wispSync }` and not the `wisp` function. Before, the CommonJS entry unwrapped the function, so `require("@cldmv/wisp")("./data.json")` worked. It now throws, because the module object is not callable.

- `require(x)(…)` becomes `require(x).wisp(…)`, or `const { wisp } = require(x)`.
- `.wisp`, `.wispSync`, `.default` and destructuring keep working.
- ESM `import` is unchanged.

The `require()` Node.js range is the same as in [v1.0.9](../v1/v1.0.9.md): `^20.19.0` or `>=22.13.0`, with the same `ERR_REQUIRE_ESM` message pointing at `import()` on older versions.

## 🔧 CI & tooling

- **`npm test` also runs the suite against the build.** The new `test:dist` script builds the package and runs the Vitest suite with `--mode=dist`, so the published `dist/` is tested as well as `src/`. `test` and `ci:coverage` call it ([#74](https://github.com/CLDMV/wisp/pull/74)).
- **The `wisp-dev` condition is set with `devCondition()`.** `test.nodeOptions` is not a Vitest option and passed nothing to the workers. The Vitest configuration now uses `devCondition()` from `@cldmv/configs` 1.4.0, which sets `resolve.conditions`, `ssr.resolve.conditions` and `test.execArgv` ([#72](https://github.com/CLDMV/wisp/pull/72)).
- **`sync-release-notes.yml` added.** The companion workflow syncs release bodies from the per-version changelog files and creates missing version tags ([#80](https://github.com/CLDMV/wisp/pull/80)).
- **`ci.yml` synced with the v4.43.0 template** ([#82](https://github.com/CLDMV/wisp/pull/82)).
- **Superseded CI runs on `next` and `hotfixes` are cancelled**, so a new push no longer queues behind runs for commits that have already been replaced. The block is synced with the CLDMV/.github v4.46.0 template ([#87](https://github.com/CLDMV/wisp/pull/87), fixes [#84](https://github.com/CLDMV/wisp/issues/84)).

## Upgrade notes

- If you load wisp from CommonJS and call the result of `require()` directly, change `require("@cldmv/wisp")(…)` to `require("@cldmv/wisp").wisp(…)`, or use `const { wisp } = require("@cldmv/wisp")`.
- `.wisp`, `.wispSync`, `.default` and destructuring work as before, and ESM `import` needs no change.
- Nothing changes for the Node.js version: `engines.node` is still `>=16.0.0`, and `require()` needs `^20.19.0` or `>=22.13.0`.
