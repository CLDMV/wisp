# `@cldmv/wisp` v1.0.9 Changelog

**Release Date**: November 2026
**Release Type**: Patch
**Branch**: `release/1.0.9`

---

## Overview

This release raises the supported Node.js version to 22.22.0 or newer and renames the CommonJS entry's source file to match its published name. JSON loading behaves exactly as in [v1.0.8](./v1.0.8.md): the only change in `src/` is the version named in the `require()` error message, and the published `dist/index.cjs` differs only in that message and its file header.

The Node.js floor is now 22.22.0. `engines.node` goes from `>=16.0.0` to `>=22.22.0`, and the bundle is now built for a Node.js 20 syntax level instead of Node.js 16. Read the upgrade notes before updating on an older runtime.

---

## 📦 Requirements

### Node.js 22.22.0 or newer is required ([#65](https://github.com/CLDMV/wisp/pull/65), fixes [#64](https://github.com/CLDMV/wisp/issues/64))

`engines.node` was `>=16.0.0`, and `require()` additionally needed Node.js `^20.19.0` or `>=22.12.0` for `require(esm)`. Both are now `>=22.22.0`. The development toolchain (chokidar 6, tsup 9) needs Node.js 22.22, so nothing older can be built or tested any more, and the published floor now says so instead of promising versions that were never exercised.

- `dist/index.mjs` is now built with esbuild's `node20` target instead of `node16`. The `import()` calls with `with` and `assert` attributes still reach Node.js exactly as written, so the attribute fallback chain is unchanged.
- The CommonJS entry's `ERR_REQUIRE_ESM` message now reads `require() needs Node.js >=22.22.0` and still points to `import()`.
- The CI test matrix starts at Node.js 22.22.0 instead of 22.12.0.

---

## 📦 Packaging

- **CommonJS entry renamed in source.** `src/cjs-shim.cjs` is now `src/index.cjs`, next to the ESM entry `src/index.mjs` it loads, so the source and the published `dist/index.cjs` share a name ([#65](https://github.com/CLDMV/wisp/pull/65), fixes [#63](https://github.com/CLDMV/wisp/issues/63)). The `wisp-dev` export condition's `require` target now points at `src/index.cjs`. Nothing changes for consumers of the published package.
- **Caller resolution through the CommonJS entry is tested.** wisp resolves relative paths from the file that calls it by skipping `index.*` entry frames in `src/` and `dist/`. New tests load the package by name from a CommonJS fixture, once with the `wisp-dev` condition (`src/index.cjs`) and once without it (`dist/index.cjs`), and check that paths still resolve against the calling file ([#65](https://github.com/CLDMV/wisp/pull/65)).

## 🔒 Security & supply chain

- The dev toolchain update moves Vite (via Vitest) from 8.3.2 to 8.3.5 and esbuild (via tsup) from 0.27.7 to 0.28.2, clearing the open Dependabot alerts ([#66](https://github.com/CLDMV/wisp/pull/66)).
- `overrides` now force `katex` to `>=0.19.1 <1.0.0` (0.16.47 → 0.19.1) and `minimatch` to `^11.0.3` (10.2.6 → 11.0.3), the patched versions ([#67](https://github.com/CLDMV/wisp/pull/67)). Both are development-only transitive dependencies; the package still has no runtime dependencies.

---

## 🔧 CI & tooling

- **The test setup passes the `wisp-dev` condition**: `resolve.conditions` and `ssr.resolve.conditions` in the Vitest configuration, and `--conditions=wisp-dev` on the `node --test` run in `test:cjs`, so loading the package by name in tests reaches `src/` ([#65](https://github.com/CLDMV/wisp/pull/65)).
- **The failed-import retry test is gated on behaviour, not the Node.js major.** Node.js 22.22 retries a URL whose first import failed on its attributes, as 24 and later do, so the old `>= 24` check ran the cached-failure test on a Node.js that no longer caches. The suite now probes the behaviour once at startup ([#65](https://github.com/CLDMV/wisp/pull/65)).

## Upgrade notes

- **Node.js 22.22.0 or newer is now required.** On an older runtime, npm warns with `EBADENGINE` (or refuses the install under `engine-strict`), and the package is no longer built or tested there. Stay on [v1.0.8](./v1.0.8.md) until you can upgrade Node.js.
- No API changes: the exports, options and JSON loading behaviour are the same as v1.0.8.
