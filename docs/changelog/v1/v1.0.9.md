# `@cldmv/wisp` v1.0.9 Changelog

**Release Date**: November 2026
**Release Type**: Patch
**Branch**: `release/1.0.9`

---

## Overview

This release renames the CommonJS entry's source file to match its published name and adds tests for caller resolution through it. JSON loading behaves exactly as in [v1.0.8](./v1.0.8.md): the only change in `src/` is the version range named in the `require()` error message, and the published `dist/index.cjs` differs only in that message, a comment explaining it and its file header.

The supported Node.js range does not change. `engines.node` stays `>=16.0.0`, since wisp exists to load JSON on every Node.js version, and `dist/index.mjs` is still built for the Node.js 16 syntax level.

---

## 📦 Requirements

### Node.js support is unchanged; developing wisp needs 22.22.0 ([#65](https://github.com/CLDMV/wisp/pull/65), fixes [#64](https://github.com/CLDMV/wisp/issues/64); [#70](https://github.com/CLDMV/wisp/pull/70))

- `import` works on Node.js 16 and later, as before. `require()` needs Node.js `^20.19.0` or `>=22.13.0`, because the CommonJS entry loads the ES module build through synchronous `require(esm)`. 22.13 rather than 22.12 because Node.js 22.12 prints an ExperimentalWarning on `require(esm)`.
- The CommonJS entry's `ERR_REQUIRE_ESM` message now reads `require() needs Node.js ^20.19.0 or >=22.13.0` and still points to `import()`.
- Developing wisp needs Node.js 22.22.0 or newer, the floor of the build and test toolchain (Vitest 5, tsup 9). That floor is declared in the new `devEngines.runtime` field with `onFail: "error"`, which npm checks only for this project's own `npm install`, `npm ci` and `npm run`, never for consumers ([#70](https://github.com/CLDMV/wisp/pull/70)).
- The CI test matrix starts at Node.js 22.22.0 instead of 22.12.0, matching `devEngines`. That is not wisp's support floor, and the workflow input descriptions now say the value must match `devEngines`, not `engines` ([#70](https://github.com/CLDMV/wisp/pull/70)).

## 📦 Packaging

- **CommonJS entry renamed in source.** `src/cjs-shim.cjs` is now `src/index.cjs`, next to the ESM entry `src/index.mjs` it loads, so the source and the published `dist/index.cjs` share a name ([#65](https://github.com/CLDMV/wisp/pull/65), fixes [#63](https://github.com/CLDMV/wisp/issues/63)). The `wisp-dev` export condition's `require` target now points at `src/index.cjs`. Nothing changes for consumers of the published package.
- **Caller resolution through the CommonJS entry is tested.** wisp resolves relative paths from the file that calls it by skipping `index.*` entry frames in `src/` and `dist/`. New tests load the package by name from a CommonJS fixture, once with the `wisp-dev` condition (`src/index.cjs`) and once without it (`dist/index.cjs`), and check that paths still resolve against the calling file ([#65](https://github.com/CLDMV/wisp/pull/65)).

## 🔒 Security & supply chain

- The dev toolchain update moves Vite (via Vitest) from 8.3.2 to 8.3.5 and esbuild (via tsup) from 0.27.7 to 0.28.2, clearing the open Dependabot alerts ([#66](https://github.com/CLDMV/wisp/pull/66)).
- `overrides` now force `katex` to `>=0.19.1 <1.0.0` (0.16.47 → 0.19.1) and `minimatch` to `^11.0.3` (10.2.6 → 11.0.3), the patched versions ([#67](https://github.com/CLDMV/wisp/pull/67)). Both are development-only transitive dependencies; the package still has no runtime dependencies.

## 🔧 CI & tooling

- **The test setup passes the `wisp-dev` condition**: `resolve.conditions` and `ssr.resolve.conditions` in the Vitest configuration, and `--conditions=wisp-dev` on the `node --test` run in `test:cjs`, so loading the package by name in tests reaches `src/` ([#65](https://github.com/CLDMV/wisp/pull/65)).
- **The failed-import retry test is gated on behaviour, not the Node.js major.** Node.js 22.22 retries a URL whose first import failed on its attributes, as 24 and later do, so the old `>= 24` check ran the cached-failure test on a Node.js that no longer caches. The suite now probes the behaviour once at startup ([#65](https://github.com/CLDMV/wisp/pull/65)).

## Upgrade notes

- Nothing to do for the Node.js version: `engines.node` is still `>=16.0.0`. Code that calls `require()` needs Node.js `^20.19.0` or `>=22.13.0`; on older versions load the package with `import()`.
